# Ручная проверка MVP

1. `docker compose up --build -d`; открыть http://localhost:8080 и http://localhost:8080/health.
2. Зарегистрировать аккаунт **А** (`alice@example.com`, пароль от 10 символов). Создать проект «Demo».
3. В приватном окне браузера зарегистрировать **B** (`bob@example.com`). Вернуться к A и пригласить B по email.
4. A: создать задачу с названием, описанием, `priority: high`, `epic: dev`, тегами `frontend,urgent`, сроком через 2 дня, назначить B. Индикатор должен быть красным.
5. B: открыть проект и нажать «Начать», затем «На ревью». Проверить ошибку при отправке без описания и URL. Добавить текст и ссылку `https://github.com`.
6. B: убедиться, что кнопки прямого завершения нет. A: «Проверить» → «Вернуть в работу» с комментарием. B: отправить заново.
7. A: «Проверить» → «Одобрить выполнение». Статус `Готово`, дата завершения выставлена.
8. A: назначить B управляющим, затем передать B владение. Проверить, что B может создать задачу; A сохраняет право удаления как создатель.
9. Проверить сессии: «Выйти», обновить защищённый URL, редирект на `/login`. В Swagger выполнить GET `/api/dashboard` с Bearer из ответа логина.
10. Проверить адаптивность при ширине 375px. Доска должна горизонтально прокручиваться.
11. Проверить запрет: без сессии GET `/api/projects` → 401, чужой проект → 403, изменение роли обычным участником → 403.

**Замечание:** Swagger UI загружается с CDN, поэтому интернет нужен только для отображения Swagger, не для самой доски.
