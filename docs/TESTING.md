# Проверка серверного MVC

1. `docker compose up --build -d`.
2. Откройте `/login` и `/register`: Go должен вернуть полный HTML-документ (без JavaScript SPA).
3. Попробуйте открыть `/projects` без входа: перенаправление на `/login`.
4. Зарегистрируйте A, создайте проект и задачу с дедлайном в течение 24 часов. На карточке должен отображаться критический приоритет.
5. Зарегистрируйте B в отдельном браузере; войдите как A, пригласите B и назначьте ему задачу.
6. Как B начните задачу и отправьте описание/ссылку на ревью. Прямая установка `done` невозможна.
7. Как A одобрите задачу: она должна стать «Завершено». Отказ возвращает «В работе».
8. Проверьте, что B не может поменять владельца проекта или роль другого пользователя.
9. Убедитесь, что POST формы без CSRF возвращает 403.
10. Проверить HTTP-ответ `curl -i http://localhost:8080/login`: есть `Content-Type: text/html` и HTML-теги `<!doctype html>`, `<form>`.
11. Откройте `/swagger`: отдельный REST API по-прежнему документирован.

В CI выполняются Go unit/integration тесты, компиляция и Docker-сборка. Интеграционные тесты с PostgreSQL требуют `TEST_DATABASE_URL` и создают/очищают тестовые таблицы. Не задавайте production базу для тестов.
