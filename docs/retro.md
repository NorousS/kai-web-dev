# Ретроспектива

1. До начала реализации нужно запускать проверочный контейнер с готовыми зависимостями, чтобы получать RED поведения,
   а не missing go.sum/embed. Общий Docker test target и CI теперь фиксируют обязательные проверки.
2. Следующие истории вести строго вертикально: один тест → реализация → проверка → commit, в отдельном контексте.
   Параллельное создание тестов и обработчиков нарушило изначально согласованный процесс; доказательства не восстанавливаются задним числом.
3. Unicode-границы должны проверяться через HTTP и CLI одинаковыми примерами; регрессионный CLI-тест добавлен.
4. Формы после изменения состояния сессии нужно проверять без дополнительного GET, скрывающего дефект.
   TestLoginFormWorksAfterStaleSession обеспечивает эту проверку автоматически.
5. Graphify помогает находить Go-связи; для SQL-навигации можно отдельно добавить tree_sitter_sql.
6. Локальная команда тестов и CI используют один Docker target, чтобы не расходились проверки окружений.
