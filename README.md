# Task Manager

Учебное приложение для собственных задач: Go, Gin, PostgreSQL, Go Templates и Bootstrap.
MVC, HTML формируется сервером. Интерфейс на русском, время — московское.

## Запуск

Нужен запущенный Docker Desktop с Linux containers. Локальная установка Go не требуется.

```powershell
docker compose up --build -d
```

Откройте http://127.0.0.1:8080. Зарегистрируйтесь и войдите в аккаунт.
При первом запуске PostgreSQL создаёт БД, затем goose выполняет миграции, после них стартует приложение.
Повторный запуск безопасен: применённые миграции не повторяются. Ошибка миграции запрещает запуск app.

```powershell
docker compose logs app migrate
docker compose down
```

Данные сохраняются в Docker volume. Не добавляйте `-v` к `down`, если данные нужны.
Тестовая БД отделена от основной и хранится в tmpfs.

Настройки необязательны: скопируйте `.env.example` в `.env` и измените порт или параметры БД.
По умолчанию приложение доступно только на этом компьютере, PostgreSQL наружу не публикуется.
Для использования через HTTPS требуется `COOKIE_SECURE=true`; локально оставьте `false`.

## Администратор

Встроенного администратора и пароля нет. После запуска выполните:

```powershell
docker compose exec app /app/taskmanager create-admin --username admin --email admin@example.test
```

Команда запросит пароль скрытым вводом. Минимум 8 символов, максимум 72 байта.
Email должен отличаться от уже зарегистрированных. Вход выполняется через обычную форму.
При работе без терминала пароль можно передать одной строкой через stdin; аргумента `--password` нет.

## Возможности

- Регистрация, вход, выход и редактирование имени/email.
- Создание, просмотр, редактирование и удаление своих задач.
- Статусы: Новая, В работе, Выполнена. Приоритеты: Низкий, Средний, Высокий.
- Необязательный срок, поиск по названию, фильтр статуса, комментарии.
- Администратор видит пользователей и любые задачи, удаляет задачи, блокирует и разблокирует обычных пользователей.
- Блокировка отзывает все сессии; после разблокировки нужен новый вход.

Название: 1–150 символов, имя: 3–50, email: до 100 и уникален без учёта регистра.
Новая задача получает статус «Новая» и приоритет «Средний».
Удаление требует подтверждения и удаляет комментарии задачи.

## Проверки

```powershell
docker compose --profile test run --build --rm test
```

Команда проверяет gofmt, сборку, `go vet ./...` и `go test ./...` в контейнере.
HTTP-тесты используют настоящую PostgreSQL и отдельную случайную схему на каждый тест.
При отсутствии `TEST_DATABASE_URL` или имени БД без суффикса `_test` тесты завершаются ошибкой.
CLI проверяется отдельным subprocess, затем созданная учётная запись входит через HTTP.

Исходники Go можно проверять локально при наличии Go 1.25+ и отдельной тестовой PostgreSQL:

```powershell
$env:TEST_DATABASE_URL='postgres://user:password@localhost:5432/taskmanager_test?sslmode=disable'
go test ./...
go vet ./...
go build ./...
gofmt -l cmd internal migrations
```

Python-кода в приложении нет; Ruff не применяется.

## Структура MVC

- `cmd/taskmanager`: сервер, миграции и команда администратора.
- `internal/model`: данные и параметризованные SQL-запросы, без Gin.
- `internal/web`: контроллеры Gin, формы, права, сессии и HTML-шаблоны.
- `migrations`: SQL goose, встроенный в бинарный файл.
- `tasks/prd-task-manager.md`: требования; `prd.json`: истории Ralph и ссылки на Issues.
- `docs/adr`: архитектурные решения; `GLOSSARY.md`: термины.

Сессия живёт 24 часа, в БД хранится SHA-256 случайного токена. Пароли хешируются bcrypt.
Каждая POST-форма защищена CSRF, пользовательский текст экранируется шаблонами.
Основные ошибки: 422 — неверная форма, 403 — запрет действия, 404 — отсутствующая/чужая задача, 503 — ошибка БД.

## Сценарий защиты

1. Зарегистрировать двух пользователей в разных браузерах/профилях.
2. Первым создать задачу со сроком, изменить статус/приоритет, добавить комментарий.
3. Проверить поиск вместе с фильтром и изменение профиля.
4. Вторым открыть прямую ссылку на чужую задачу: ожидается 404.
5. Администратором открыть все задачи и пользователей, заблокировать первого пользователя.
6. Убедиться, что старая сессия закрыта. Разблокировать и войти заново.
7. Удалить задачу с подтверждением; повторное открытие даёт 404.
8. Перезапустить Compose и показать сохранённые учётные записи.
